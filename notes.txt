So what will be our flow    --------->>>>>>>>>   It’s not two calls, because the base price is already stored on the performer record (basePrice). You load the performer anyway to show their profile, so the only extra query is the peak-price check.

Flow for a price on a specific date

Load the performer (you already have basePrice).
Query PeakPrice once: this performer, where from <= date <= to.
If a record comes back, the price is peakPrice. If not, it’s basePrice.

That’s one extra query, and your compound index makes it fast. Put this logic in one function (the pricingService.js from our folder structure) and use it everywhere, so the price is never calculated in two different ways.
